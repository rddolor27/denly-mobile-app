# Denly — Mobile (denly-mobile)

React Native + TypeScript app for Android and iOS (ADR 0010: a working Android app first). Minimum device **iPhone 13** (390 × 844 pt, notch, safe
areas 47 pt top / 34 pt bottom). This repo is independent of `../denly-backend` — it consumes the
backend only through its HTTP API. Never import from it; never add a monorepo.

Scaffolded 2026-09-23. Frontend only, example data: NativeWind theme + React Native Reusables kit
+ Denly components (plan 0003, ADR 0009) and every screen of the clickable prototype
(https://claude.ai/artifact/CqH9SLrozEcZYPLMcZApQJ) with its states, driven by the in-memory demo
store (`src/features/demo/`, `useDemo()`; Profile → demo controls switch connection, pack and
scan outcome). Also the typed API client (not called yet) and the detector port types. No real
camera, detector adapter, backend calls or offline data packs yet — add each only when asked.

## Stack (as built)

- **Expo SDK 57** (React Native 0.86.3, React 19.2.3, TypeScript 6.0, Hermes, New Architecture,
  React Compiler on) as an **Expo dev build** with Continuous Native Generation: `ios/` and
  `android/` are generated by `expo prebuild` and git-ignored — native changes go through
  `app.json` / config plugins. Expo Go is out (the detector is a native module).
- Navigation: **Expo Router** 57, typed routes on, routes in `src/app/` (thin files that re-export
  screens from `src/features/`)
- Camera: `react-native-vision-camera` with a native frame-processor plugin for real-time detection
  (ADR 0004) — **not installed yet**
- On-device detection: YOLOv8 exported to Core ML, bundled in the app (ADR 0002) · runtime
  integration: decided at the first detection spike · model lock file: `model/model.lock.json`
  (planned path; weights `*.mlmodel`/`*.mlpackage` are git-ignored)
- Offline mode: downloadable small / medium / large SQLite data packs (ADR 0003) · `expo-sqlite`
  is installed (its kv-store holds the appearance preference); the pack wrapper comes with the
  offline feature
- Styling (ADR 0009): **NativeWind 4 / Tailwind 3**; tokens in `src/global.css` (HSL vars, light
  `:root` + `.dark:root`) mirrored in `src/lib/theme.ts` (sync + contrast tests); React Native
  Reusables components in `src/components/ui/` (owned, restyled); Denly components in
  `src/components/denly/`; icons `lucide-react-native`; display font Bricolage Grotesque
  (500/700), body = system font; appearance System/Light/Dark via `useAppearance()`; `cn()` in
  `src/lib/utils.ts` (tailwind-merge v2, taught the named text sizes); `/design` dev route shows
  every component
- Server state: **TanStack Query** 5 (`src/lib/query-client.ts`; `focusManager` wired to
  `AppState`; `onlineManager` on its default until a connectivity library is chosen) · client
  state: React state/context
- API client: `src/lib/api/` — `createApiClient` over `fetch`, base URL + 10 s timeout from
  `src/lib/config.ts`, `x-request-id` per request, every failure an `ApiError { status, code,
  message, requestId }`, every response checked by a hand-written type guard (schema library is
  open decision #11). The base URL includes the backend's `/api` prefix (ADR 0012), so the client
  calls `/health` and `/v1/...` relative to it; the contract is the backend's OpenAPI at
  `/api/docs-json`. Only `health()` exists and no screen calls it yet. Auth (ADR 0012, planned,
  not built): refresh token in the Keychain (`expo-secure-store`, not installed yet), access
  token in memory, one in-flight refresh at a time (a replayed refresh token signs the user out).
- Package manager: **pnpm 10** with `node-linker=hoisted` (`.npmrc`; Metro needs a flat
  `node_modules`) · Node ≥ 24
- iOS: bundle id `app.denly.mobile` (placeholder — change before the first EAS build), app name
  "Denly", scheme `denly`, portrait only, iPhone only (`supportsTablet: false`), `platforms:
  ["ios", "android"]`, minimum iOS **16.4** (Expo SDK 57 default deployment target) · Android
  package `app.denly.mobile`, adaptive icon from the placeholder `icon.png`
- Tests: Jest 29 via `jest-expo` (base preset — the `jest-expo/ios` preset fails to strip Flow in
  `@react-native/jest-preset` here) + React Native Testing Library 14 (async `render`, `userEvent`)
- Lint: `expo lint` (ESLint 9 flat config, `eslint-config-expo`) + `no-console: error`
- TypeScript: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`,
  `exactOptionalPropertyTypes` all on; `types: ["jest"]` because TS 6 no longer auto-includes
  `@types/*`; `src/env.d.ts` types `process.env` for a fresh clone

## Commands

```bash
pnpm install                 # install (hoisted)
pnpm start                   # Metro for the dev client
pnpm ios                     # macOS only: expo run:ios (prebuild + build + install)
pnpm android                 # expo run:android (prebuild + Gradle + install)
pnpm prebuild                # regenerate ios/ (clean)
pnpm prebuild:android        # regenerate android/ (clean)
pnpm typecheck               # tsc --noEmit
pnpm lint                    # expo lint
pnpm test                    # jest --maxWorkers=3 (never --watch in a Claude session)
pnpm doctor                  # expo-doctor (via pnpm dlx)
pnpm export:android          # production Android bundle to dist/
pnpm export:ios              # production iOS bundle to dist/ (needs EXPO_PUBLIC_API_URL, https)
eas build --profile development|preview --platform ios   # needs eas login — never run by Claude unasked
```

This machine is Windows: no Xcode, no simulator. Verify with typecheck, lint, test, doctor and
`export:ios`; native builds go through EAS or a Mac.

CI/CD (ADR 0013, GitHub Actions, all third-party actions pinned to a commit SHA): `CI` on every PR
and push to `main`; `Build Production (release)` on a published GitHub Release (tag must equal
`v` + `app.json` `expo.version`) runs an EAS production build (no `eas submit`); `Build Preview
(manual)` (`workflow_dispatch`) runs an EAS preview build against a chosen ref/platform. Details
and one-time setup in `README.md`.

## Layout

```
src/
  app/                  Expo Router routes: _layout.tsx (fonts, appearance, providers, PortalHost),
                        index.tsx (redirect), (auth)/, (tabs)/ (custom TabBar), scan/, settings/, design.tsx
  features/<feature>/   <name>.screen.tsx, components/, hooks/, (api/, types/, utils/ when needed)
  features/demo/        example data + in-memory store (DemoProvider/useDemo), replaced screen by screen
                        by TanStack Query hooks and the auth session
  features/toast/       the one toast (useToast + Toast) every screen uses
  features/scan/        camera (simulated viewfinder), processing, results, ingredient detail
  features/scan/detection/  detector port (IngredientDetector, DetectionRun, DetectionResult) — the adapter
                        added here later is the only code that knows YOLO / Core ML exist
  features/scan/intelligence/  (later) offline evaluator over the data pack — must pass the conformance suite
  features/offline-data/    tier picker with a simulated download; verify, install, update come later
  components/ui/        React Native Reusables components, restyled to Denly
  components/denly/     Denly components (rows, tiles, ConfidenceLabel, HeroCounterCard, TabBar, Screen, …)
  lib/                  config.ts, logger.ts, query-client.ts, api/, theme.ts (tokens + NAV_THEME), utils.ts (cn),
                        appearance.ts + use-appearance.ts, use-theme-colors.ts, color.ts (contrast maths)
  global.css            design tokens for NativeWind
```

Tests sit next to the code as `*.spec.ts(x)` — never inside `src/app/` (Expo Router would treat
them as routes).

## Rules that matter most here

- Load the `react-native` skill for anything in `src/`; the `ui-ux` skill for any screen or state;
  the `computer-vision` skill for the detection feature and the model.
- Every screen ships its loading, empty, error and offline states; detection results render even
  when the LLM explanation is unavailable.
- The image never leaves the phone: detection runs on the device through the detector port and
  only the `DetectionRun` JSON is submitted. The captured file is deleted after the scan.
- Model weights are never committed; the build fetches the pinned model from the lock file and
  verifies its SHA-256. Measure the model on a physical iPhone 13, not the simulator.
- Online → the backend answers (with AI summary); offline → the offline evaluator answers from the
  installed data pack, labelled offline, no summary. Packs are verified before an atomic install
  and opened read-only; the evaluator passes each data release's conformance suite.
- Accessibility is a requirement: labels, roles, 44 pt targets, Dynamic Type, non-colour signals.
- Env names live in `.env.example` (`EXPO_PUBLIC_API_URL`); env is read only in
  `src/lib/config.ts`; no secrets in the bundle. Logging only through `src/lib/logger.ts`.
- The palette is decided (ADR 0009): change token values in `global.css` and `lib/theme.ts`
  together, never role names; the sync and contrast specs guard both.
- Comments explain a non-obvious why only; don't point at prototype internals or restate code.
